# OSRS Ironman Progression Planner — Phase 4 review package

**P4-001 task board and daily-use navigation is delivered for independent review, CEO review and Owner Phase 4 acceptance.** Phases 1–3 are Owner-accepted (ADR-022); bounded Phase 4 authorization is ADR-023. The routing ambiguity remains Owner-deferred; Phase 5 is not authorized.

This is a locally hosted, browser-origin IndexedDB roadmap editor for a single private, noncommercial player. Phase 3 adds local port-aware layout, visual groups, completed visibility and Focus/Highlight to the Phase 2 progression/backup workflows. It starts with **your own empty roadmap**, not the canonical sample. Optional **Load original demo…** replaces the active roadmap with a copy of the original seven-node/six-edge fixture. Demo relationships are player-defined examples, **not verified game prerequisites**. No Jagex artwork is included.

## Windows quick start (Chrome or Edge)

1. Use this existing `Phase1/osrs-phase1-editor` working folder. Only when restoring an archive, extract to a new separate folder; do not overwrite the working copy.
2. Install **Node.js 20+** if necessary. In this `osrs-phase1-editor` folder, open Windows **Command Prompt**: click the Explorer address bar, type `cmd`, Enter.
3. Run **`npm run dev`**. No package installation is needed; ELK.js is bundled locally. **Keep this terminal window open.** Alternatively double-click `START_WINDOWS.cmd` in this folder, which keeps the window open if the server exits unexpectedly.
4. Open **http://127.0.0.1:4173/** exactly (not `file://`, not the old folder, and do not alternate between `localhost` and `127.0.0.1`). IndexedDB is scoped to this **browser + origin**.
5. The page should read **LOCAL-FIRST GOAL EDITOR · PHASE 3**. If an older demo appears, press **Ctrl+Shift+R** and verify the terminal's current folder. Use `npm run dev` for this delivery; the preserved `dist/` remains Phase 1. The separately validated build is under `evidence/phase3-2026-10-26T19-14-39-604Z/static/`.
6. Stop the server with **Ctrl+C** in its Command Prompt window. The roadmap remains in that browser's IndexedDB unless browser/site data is cleared.

**If the URL does not connect:** `npm run dev` should stay active without returning to the prompt. Try `START_WINDOWS.cmd` / Command Prompt instead of Git Bash. Check port 4173 in a second Command Prompt with `netstat -ano | findstr :4173`; use `taskkill /PID <actual-number> /F` to stop an old stale process. Never terminate a process until verifying its PID. Rerun the current server, then hard-refresh. If you use a different hostname, port or browser profile, you will see **different local data**.

## Editor controls

- **Create:** double-click truly empty canvas space for a small editor near the pointer: title, category, **Create goal**, **Cancel**, **More details**. More details transfers the unsaved fields and intended canvas position into the right-side inspector, where notes/status/counters/icons remain available. Cancel/Escape never creates a node. Creation keeps title/category first, with optional Progress disclosure. The inspector starts closed.
- **Region selection / bulk actions:** hold **Shift** and drag from empty canvas around whole goal cards. Only fully enclosed rendered cards are selected; partial cards, offscreen cards outside the rectangle, hidden goals and collapsed summaries are excluded. New rectangles replace the selection. Check marks/borders and the toolbar count show the explicit scope. Normal canvas dragging still pans; **Escape** or **Clear selection** clears selection while leaving editor drafts intact. A normal goal click selects only and preserves source → Shift-click destination pairing. Empty click clears selection without changing roadmap data; the region toolbar is hidden when selection is empty.
- **Apply to selection:** choose a manual status and **Set status…**, **Group selection…**, choose an existing group and **Add to group…**, or **Ungroup…**. Review the action/count/title-and-ID list, then Apply or Cancel. New groups require a name. Bulk actions never include other group members, prerequisites or downstream goals. Counters and positions stay unchanged. Moving a representative clears its former group's invalid reference; unselected members stay intact. Existing inspector grouping remains available. Apply asks before discarding a dirty editor draft; Cancel/declining discard leaves it untouched.
- **Edit:** single-click selects only; double-click a goal opens title/category/manual status/counters. More details opens the inspector for notes/icons/grouping. Use the right-edge **Open details / Close details** arrow to toggle it; hiding/reopening preserves drafts. Drag its left resize handle, or focus the handle and use arrow keys. Replacing/discarding dirty drafts asks first; selecting/moving goals or opening/canceling a connection preserves them. Panel changes never Fit or move goals. The full catalog is **not** implemented.
- **Move / pan / zoom:** drag a card body to move it, drag empty canvas to pan, wheel to zoom (10–220%); **Fit graph** gives an overview. **Optimize layout** explicitly runs local ELK.js with port-aware orthogonal routes and actual compact/detailed sizes. It changes node positions through Undo/Redo; it never changes IDs, statuses, counters or relationships. Later edits/dragging/filtering never trigger automatic layout. Large-graph production hardening remains Phase 6.
- **Connect, method A:** drag the **right + output port** to another goal's **left ● input port**. A quick editor opens at release, showing source → destination and type. Choose `hard`, `soft`, or `order`, then **Create connection**, Cancel or More details. More details transfers endpoints/type to the inspector without creating an edge. Card-body dragging remains movement.
- **Connect, method B:** mouse-click source, hold **Shift** and mouse-click destination, then **Connect selected nodes**. The same quick editor opens near that control. Check direction/type, Create, Cancel, or transfer to More details. One type per ordered source → destination pair; reversed endpoints are distinct but hard cycles/duplicates are rejected.
- **Edit/delete edges:** single-click selects; double-click opens source → destination, relationship type, validated Reverse direction and confirmed Delete. More details retains the selected type. Goal deletion remains in Open details and removes incident links only.
- **Context actions:** right-click a goal, edge, group or empty canvas, or focus it and press **Shift+F10 / Context Menu key**. Goal menus provide manual status, rename, counters, reviewed grouping, directional Focus and Open details. Connection menus provide type, atomic validated reversal, confirmed deletion and Open details. Groups provide rename/collapse/expand/details; empty canvas provides Create here/Fit/Reset focus. Menus on selected cards are explicitly labeled with the selection count and use the existing reviewed bulk actions. Outside objects are single-object targets even while other cards are selected.
- **Cursor keyboard/drafts:** arrows/Home/End navigate menu items, Enter submits forms, and Escape or Cancel/Close returns focus to the initiating object/control/viewport. Panels stay inside the visible window. More details transfers unsaved fields (including quick rename/counter/group-name edits); replacing a dirty inspector draft asks first, and declining keeps both drafts. Background gestures pause while the modal surface is open; close it before panning/dragging. Menu opening alone changes no data. Counters never infer completion; reversed edges keep their IDs and reject conflicts without changing the original.
- **Undo/redo:** use left buttons or Ctrl+Z / Ctrl+Y (not while editing a text input). Includes node/edge creation, edits, deletion, move and Optimize Layout. **History does not survive page reload.** Saved graph state does.
- **Density/groups:** choose compact/detailed, then explicitly Optimize when needed. Scroll the left sidebar to **Visual groups**: Create or choose/Edit a group, check members, choose an optional independent representative, and Save. A member moves from its previous group; any former representative reference is cleared safely. Collapse/expand via the editor or selected-group button. Delete defaults to ungrouping goals, with confirmation and Undo. Click **Inspect links** on a summary or the group editor to inspect original incoming/outgoing goal-to-goal connections by type/direction/endpoints.
- **View / Help:** scroll the sidebar to **View** for completed visibility and directional Focus/Highlight. **Help / Diagnostics** contains Controls, relationship effects and fail-next-save. Save state and Retry remain visible above the canvas with details closed. Full labels are **Required prerequisite**, **Recommended preparation**, **Preferred order**; edge badges abbreviate these with full-name tooltips. Only Required prerequisite (`hard`) blocks readiness.
- **Completed visibility:** Show, Dim, Hide, or Collapse completed branches. Collapse creates expandable component summaries, never new stored relationships. The representative milestone retains its own status/counters; it never represents completion of its drops. Hidden goals remain canonical prerequisites. New summaries can occupy more space than the cards they replace; use explicit Optimize if needed.
- **Focus/Highlight:** select any canonical goal (including hidden goals), choose Upstream/Downstream/Both, then Focus or Highlight. All edge types count for navigation; traversal terminates on cycles. Both means ancestors union descendants, not unrelated siblings reached by undirected traversal. Focus narrows scope; Highlight keeps scope and fades unrelated goals. Completed/group visibility still applies. **Exit Focus / Highlight** keeps the completed mode; **Reset scope and completed visibility** restores full scope + Show. Neither moves nodes or resets zoom/pan. Use Fit separately if desired.

Status and counters change only through **Save goal**. Counters require finite current ≥ 0 and target > 0; they never infer completion. Readiness uses all canonical incoming hard relationships, including collapsed/offscreen goals. The UI states “Based on prerequisites you’ve added.”

Backups are the full `schemaVersion: 1` document (including IDs, edge kinds, statuses, counters, positions, groups, preferences, catalog and icon references), with a 64 MiB export/import safety limit and existing collection limits. Images are **not embedded**; preserve original asset packages separately. Unknown/unavailable icon references fall back safely without becoming external URLs. Applied in-memory changes are exportable even after autosave failure; unsaved editor drafts and session undo history are not part of a backup. Verify the download exists before acknowledging it. Import replaces the whole roadmap; no merge. Failed replacement is not queued for automatic Retry; review the preview and confirm replacement again.
