# Architecture decisions and owner-level ambiguities — 2026-10-25

## ADR-001: HTML nodes + SVG relationships on vanilla ES modules — Phase 0 adopted, later reassess

Problem: need rich/complex editable goals, native controls, ports, labels, grouping and accessible hitboxes, statically deployable without React. Options: (A) native HTML/SVG renderer with custom gestures; (B) Cytoscape.js canvas with separate overlay; (C) React-based flow editor requiring preferred-stack change. **Spike adopts A** as a low-dependency proof; actual drag, form editing, ports, selectable edge labels, and collapsed group projection are browser-tested. Tradeoff: future layout/routing/virtualization work remains ours. No React/server architectural exception needed. Change impact: future ELK integration can retain model and DOM renderer. The other libraries were **not benchmarked or rejected on empirical performance grounds**.

## ADR-002: Replaceable layout adapter; custom layering is only a small-graph fallback — RATIFIED 2026-10-25

**Owner direction:** HTML/SVG renderer stays; no approval of the existing layered algorithm as a large-roadmap solver. Phase 0 addendum ran a three-fixture benchmark of current JS layout vs **Graphviz `dot` 2.42.4**, a mature directed layout candidate, using the same canonical model and position-only outputs; see `evidence/layout-benchmark.json`. All six benchmark runs had zero card-box overlaps and unchanged graph semantics. The chain-heavy fixture remains 81k–91k px wide, mostly because 249 successive ordered goals impose a long left→right rank sequence. On the 110-node representative, `dot` was narrower but taller, not a universal quality win. Its edge routing was generated by Graphviz but was not integrated into the prototype SVG renderer.

**Choice:** Keep a swappable renderer-independent position/routing adapter, and use the existing simple implementation only for the small Phase 1 editor demonstration. Target **ELK.js layered** for a future browser-bundled adapter (not installed/run in this environment due npm DNS failure). Graphviz is an empirical comparator, **not** a deployable runtime dependency: a CLI binary is incompatible with a browser-only static deployment absent a separately evaluated WASM build. Require ELK.js integration, port-aware routing, overlap/crossing verification and scoped-navigation acceptance in Phase 3; measure 250/400 production performance/browser memory in Phase 6. Never change stored relationships during optimization. No data migration, as the adapter emits coordinates and optional route geometry only.

## ADR-003: Normalized roadmap, no duplicate group memberships — proposed

Canonical nodes/edges/groups live in one versioned roadmap; `groupId` resides on node; representative ID is only a reference to a member node. Visual summary is a separate render projection with **no synthetic semantic edges**. One authoritative manual node state across graph/board. Data migration: none until Phase 1 persistent state is built.

## ADR-004: One typed edge per ordered pair — OWNER RATIFIED 2026-10-25

Exactly one edge for each ordered source→target pair, carrying exactly one of `hard`, `soft`, `order`. Edit the existing type rather than adding a parallel edge. Reverse source/target orientation is a distinct ordered pair, but hard-only cycle validation still applies. `validateRoadmap` and `tryAddEdge` already enforce this. No migration: Phase 0 state is not persistent.

## ADR-005: Collapsed group counts boundary edges, no invented shortcuts — OWNER RATIFIED 2026-10-25

A summary shows name, member count, external relationship count, and obvious expand action. The stored flat graph retains all original endpoints/edges. Do **not** create summary→outside semantic edges. A type/direction and endpoint breakdown is a Phase 3 enhancement. Demonstrated in the existing projection spike; no status propagation.

## ADR-006: Personal, noncommercial use; authentic icons sought only when lawful — OWNER CLARIFICATION 2026-10-25

The product is for one person's private, local, noncommercial use, not publication, sharing, monetization or distribution. The owner wants authentic OSRS item/quest/skill/boss imagery **where lawful**; original placeholder art is a fallback, not permanent design substitution. Personal use is not automatic permission. As of this addendum, **no Jagex images were imported or bundled**, and Jagex's [Fan Content Policy](https://legal.jagex.com/docs/policies/fan-content-policy), especially 6.1.3 (software/applications), leaves third-party game-art use unlicensed by this project. Check policy and source-specific rights before any catalog package or distribution; unresolved rights are an asset packaging concern, not a reason to block unrelated editor work.

## ADR-007: Safe defaults; not escalated as product ambiguities

- Connection direction: source right output → target left input, arrows and inspector text confirm, select-two later with explicit ordering.
- Creation gesture vs pan: double-click truly empty canvas only; node/handle/edge hit areas stop propagation. Not implemented until Phase 1.
- Canvas state: coordinates and optional viewport preferences persist; manual positions update only after drag/Optimize, not on viewport actions.
- Hard DAG validation: reject hard cycles on proposed updates; allow other cycles with visited sets.
- Deletion: confirm node deletion; incident edges removed only; group deletion ungroup-by-default; undoable in Phase 1.
- Autosave: retain previous committed IndexedDB snapshot; report pending/failed state visibly and allow retry; not implemented in POC.
- Desktop/mobile targets: propose evergreen Chrome/Edge/Firefox/Safari plus current mobile Safari/Chrome; support claims require actual testing.

## ADR-008: Original local PNG/WebP and missing-icon fallback — PHASE 0 FEASIBILITY VALIDATED

Immutable `src/catalog/reference.js` holds source-qualified reference records and attribution/package permissions. `src/assets/resolve.js` is an allowlisted asset registry that maps catalog defaults/temporary `iconOverride` IDs to **same-origin relative** PNG/WebP/SVG paths. A broken image triggers a one-time original SVG fallback. No arbitrary file system paths, untrusted SVG markup, or CDN. The Phase 0 inspector allows **only fixed test references** to prove override semantics, not a production custom import UI. Proven by Chromium inline-harness and Node tests; HTTP-served build bytes separately validated. Full import/retention/backup is reserved for later authorized phases. See ARCHITECTURE.

## ADR-009: Custom asset persistence and backup contract — PROPOSED FOR PHASE 1/2 IMPLEMENTATION

Phase 1 user-file selection via explicit `<input type=file accept=image/png,image/webp>`; check file signature, image decode, dimensions, count/size quotas, write bytes to IndexedDB `assets` under generated `user:<opaque-id>`, then reference that ID via `node.iconOverride`. Store assets separately from roadmap metadata; never embed binary assets in graph rendering state. A manually supplied `public/user-icons/` directory can instead be copied into a **private** local build with an explicit asset manifest. Phase 2 JSON exports must include the referenced user assets (base64 with size/count limits and provenance) OR fail with an explicit alternate companion-package workflow and import verification: no silent icon loss. Source permissions and attribution are per-asset fields; do not bundle unlicensed art in transferable source distributions. Migration of unrecognized references must retain node data and show placeholder rather than delete unknown icons. Final import limits/schema to be validated in Phase 1/2; no actual durable storage implemented now.

# Phase 1 implementation decisions — 2026-10-25 (owner-authorized phase)

## ADR-010: Single `RoadmapStore` and whole-document IndexedDB transactions — implemented

Options: (A) one schema-validated document stored atomically in IndexedDB, with command snapshots and bounded in-memory undo/redo; (B) independent node/edge tables and multi-object transaction choreography. Chose **A** for the single-roadmap v1 scale and simpler crash consistency, subject to later profiling. Stored `schemaVersion` stays 1; storage key is `osrs-ironman-roadmap` / `documents` / `active`. Command-generated changes serialize through `SaveCoordinator`; only transaction completion can produce `Saved`. Failed writes preserve previous committed data and expose Retry. Undo/redo is limited to session memory, maximum 80 history entries. Whole-snapshot writes may become expensive at scale; reassess in Phase 6 with actual measures before introducing partial writes.

## ADR-011: Phase 1 source/destination selection and editing safety — implemented

Ratifies existing C7 semantics without new product scope: click the source node, **Shift-click destination**, then Connect; the right sidebar exposes source, destination and kind before confirming. Port-to-port drag uses the same connection form. Duplicate/self/hard-cycle checks run against a proposed full document **before** replacing state; editing an edge type uses identical validation. Double-click empty canvas creates only a draft; Save commits, Cancel abandons. Switching away from a dirty editor requires discard confirmation. Node and edge deletion confirm; node deletion deletes only incident edges. Manual status/readiness remain Phase 2. The canonical fixture remains an optional resettable demo, never the default user roadmap.

## ADR-012: Phase 1 icons restricted to approved bundled references — implemented; optional upload NOT authorized

Owner's Phase 1 authorization explicitly made ADR-009's file picker optional only with separate authorization. We retained original PNG/WebP test icon references, allowlisted overrides, immutable demo catalog and local fallback. **No user file picker/blob storage was added**. This avoids expanding scope or falsely promising portable JSON before Phase 2. A future user-supplied folder must have explicit private local manifest/permissions; the transferable archive includes no Jagex assets.

## ADR-013: Outstanding browser-origin E2E evidence — OPEN gate item

Engineering sandbox blocks navigations to served `http://127.0.0.1:4173/`. Unlike a normal browser test, an inline DOM+data-module harness executes interactive elements with a **mock IndexedDB** and is labeled as such. Independent real HTTP asset serving works, but only the owner or another unrestricted browser environment can validate true IndexedDB persistence and full refresh recovery. **Do not upgrade this to an E2E pass**. Phase 1 implementation can be handed off, but final acceptance should wait for the owner-run recovery/failure checklist in README.

Prior ADR-004 (one edge per ordered pair), ADR-005 (collapsed summary with boundary count), ADR-006 (private lawful art), and ADR-002 (replaceable nonproduction layout) remain unchanged.
